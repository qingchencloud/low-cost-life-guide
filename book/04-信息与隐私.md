# 04-信息与隐私

> 传播速度不等于证据强度，公开范围也不等于可控范围。

> 先看风险与止损，再看错误建议；指数只用于编辑排序。

## C07 · 把密钥、令牌和配置直接提交到公开仓库

> **反面示例｜请先看风险与止损。** 反面示例｜任何进入公开仓库的凭证都应按已暴露处理。

- 低性价比指数：**98 / 100**
- 严重度：**critical**
- 证据等级：**A**
- 最后更新：**2026-09-28**

### 反面建议（分析材料）

> 先把密钥写进配置文件，项目稳定后再清理。

### 场景

调试时把 TOKEN、API key、数据库密码或个人数据放入代码、Issue 或日志。

### 为什么会被吸引

复制粘贴最快，马上能跑；轮换和清理被推迟到未来。

### 隐藏成本

- **钱**：云资源、API 额度和账户可能被滥用。
- **时间**：需要排查提交历史、轮换凭证和恢复服务。
- **机会**：事故处理会打断交付，并影响合作信任。
- **其他**：删除当前文件不能消除 Git 历史中的旧凭证。

### 失败机制

- 误把私有开发环境的安全假设带到公开协作环境。
- 认为删除文件等于撤销凭证。
- 没有在提交前做 secret scanning。

### 证据与来源

- **A** GitHub Docs：Removing sensitive data from a repository [https://docs.github.com/en/code-security/tutorials/remediate-leaked-secrets/remediating-a-leaked-secret](https://docs.github.com/en/code-security/tutorials/remediate-leaked-secrets/remediating-a-leaked-secret)：官方文档明确说明撤销凭证、清理历史和后续验证的重要性。

### 何时止损

- 立即在凭证提供方撤销或轮换泄露的密钥。
- 检查访问日志、费用和异常资源，再清理仓库历史。
- 改用环境变量、密钥管理服务和提交前扫描。

### 更稳替代

把配置与代码分离，使用本地 .env、CI secrets 和最小权限令牌；公开仓库只保留示例配置。

### 决策前自检

- 这个值是否能访问真实资源？
- 提交历史和构建日志是否也会保存它？
- 泄露后能否在几分钟内撤销？


## C10 · 只看标题和短视频，就替自己做重大决定

> **反面示例｜请先看风险与止损。** 反面示例｜重大决定至少要回到原文、原始数据或专业来源。

- 低性价比指数：**79 / 100**
- 严重度：**medium**
- 证据等级：**C**
- 最后更新：**2026-09-28**

### 反面建议（分析材料）

> 看几个热门观点，就足够判断事情真相。

### 场景

在健康、投资、工作和公共事件上，只凭标题、剪辑或转述做结论。

### 为什么会被吸引

信息短、情绪强、结论确定；完整材料通常枯燥、矛盾且需要时间。

### 隐藏成本

- **钱**：错误判断可能带来购买、投资或合同损失。
- **时间**：反复纠错和争论比最初核查更耗时。
- **机会**：错过真正重要的细节和反例。
- **其他**：转发错误信息会损害可信度。

### 失败机制

- 把传播效率误当成证据强度。
- 忽略样本、时间、利益关系和反方材料。
- 让情绪先完成判断，再寻找支持自己的证据。

### 证据与来源

- **C** 信息核查复盘：从标题回到原始材料（匿名复盘或待核实材料）：经验性案例；涉及高风险事项时应查官方或原始来源。

### 何时止损

- 涉及金钱、健康、法律或隐私时暂停转发和行动。
- 找到原文、发布日期、作者和利益关系。
- 把确定事实、推断和未知项分别写出来。

### 更稳替代

用短内容发现线索，用原始材料做决定；当信息不足时明确保留判断。

### 决策前自检

- 我看到的是原始材料还是二次转述？
- 哪些关键数字和限制条件被省略了？
- 有没有反方来源或相反案例？


## C16 · 把密码复用当成方便

> **反面示例｜请先看风险与止损。** 反面示例｜一个服务的泄露，不应自动打开其他服务。

- 低性价比指数：**99 / 100**
- 严重度：**critical**
- 证据等级：**A**
- 最后更新：**2026-09-29**

### 反面建议（分析材料）

> 重要账号记一个强密码，其他地方都复用它。

### 场景

多个网站、邮箱、支付和开发平台使用相同或高度相似的密码。

### 为什么会被吸引

记忆和输入成本最低，直到某个服务发生泄露。

### 隐藏成本

- **钱**：支付、云服务和购物账户可能被连锁访问。
- **时间**：需要同时找回、轮换和核对多个账户。
- **机会**：事故响应会打断工作和交付。
- **其他**：邮箱一旦失守，可能成为重置其他账户的入口。

### 失败机制

- 把不同服务的安全边界当成一个边界。
- 忽略历史泄露和弱密码猜测风险。
- 没有启用多因素认证和恢复方式。

### 证据与来源

- **A** CISA：Use Strong Passwords [https://www.cisa.gov/secure-our-world/use-strong-passwords](https://www.cisa.gov/secure-our-world/use-strong-passwords)：官方建议使用强且唯一的密码，并配合密码管理器和多因素认证。

### 何时止损

- 先保护邮箱、支付和开发平台等高价值账户。
- 为每项服务使用唯一凭证并启用多因素认证。
- 发现泄露时从提供方和登录记录开始核查，不只改当前页面。

### 更稳替代

使用密码管理器生成唯一凭证，保留离线恢复方式和安全联系人。

### 决策前自检

- 这个密码是否在别处使用过？
- 账号是否有多因素认证？
- 恢复邮箱和设备是否仍可控？


## C17 · 把公开个人信息当成免费的营销资产

> **反面示例｜请先看风险与止损。** 反面示例｜公开信息一旦被复制，删除不等于收回。

- 低性价比指数：**90 / 100**
- 严重度：**high**
- 证据等级：**C**
- 最后更新：**2026-09-29**

### 反面建议（分析材料）

> 先把所有真实细节发出来，流量起来后再考虑隐私。

### 场景

发布作品、求职、直播或经营个人品牌时，把可识别信息混在内容和截图里。

### 为什么会被吸引

真实细节更容易引发互动，隐私风险却是延迟出现的。

### 隐藏成本

- **钱**：骚扰、诈骗和账号恢复可能带来直接损失。
- **时间**：需要删除、申诉、解释和持续监控。
- **机会**：过度暴露会限制未来换工作、迁居或休息的自由。
- **其他**：家人、同事和客户可能被连带识别。

### 失败机制

- 把传播速度当成可控范围。
- 忽略截图、缓存和二次转载。
- 没有区分公开身份、工作身份和私人身份。

### 证据与来源

- **C** 隐私复盘：公开内容的长期可见性（匿名复盘或待核实材料）：经验性案例；具体平台安全设置需要逐项核对。

### 何时止损

- 撤下仍可定位住址、行程、联系方式或账户恢复线索的内容。
- 把公开内容与工作、家庭、支付身份分层。
- 为必须公开的信息设置最小化和定期复核。

### 更稳替代

公开作品和方法，不公开能定位个人生活的组合信息。

### 决策前自检

- 陌生人能否据此推断我在哪里？
- 这条内容被永久保存后还能接受吗？
- 是否会牵连家人、客户或同事？
